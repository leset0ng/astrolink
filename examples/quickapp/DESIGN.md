# Astrolink QuickApp design

The parent-provided single-page wireframe governs this Operate surface. Developers first read real connection state, then scan or advertise, choose a peer, run echo tests and release resources. This is a narrow Vela touchscreen app, not a web page.

The OLED ground is black (`#000000`), selected for watch display and indoor bench use. Main text is white; secondary copy uses cool light neutrals. Controls use muted blue (`#253c59`, primary `#355f91`) and connected state uses light green (`#8fe0b5`). Native error results use readable salmon (`#ffb3a6`). There are no decorative images, shadows, motion, external fonts or network assets.

A single native list scrolls all content. The first viewport contains the title, status, scan/advertise controls, and the start of peer discovery. Actions are at least 52 px high; the 200 px breakpoint reduces horizontal padding and typography without reducing control heights. Peer IDs truncate, while errors and event messages wrap. Counters and limits stay near the message actions they describe. The log is bounded to 20 entries; peer history to 12 entries.

Use firmware system typography to keep Chinese text legible and to avoid extra font memory. Interface copy names the current action and states what to do next. Busy actions disable controls; empty discovery state tells users to advertise on the other device. Missing native features and unsupported firmware are explicit states.

The launcher icon is authored geometry generated by `scripts/make-icon.py`; its PNG embeds source provenance. It uses the same blue/white/black palette.

Validation: TypeScript and controller tests pass, and the real aiot-toolkit RPK build succeeds. Native simulator screenshot inspection remains pending the integration environment and is not claimed by this design record.
